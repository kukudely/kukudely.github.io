## 题目描述

[LeetCode 1：两数之和](https://leetcode.cn/problems/two-sum/)

**难度：简单**

给定整数数组 `nums` 和目标值 `target`，找出数组中和等于 `target` 的两个元素，返回它们的数组下标。

- 每种输入都恰好存在一个有效答案。
- 两个元素必须来自不同的下标，同一个元素不能重复使用。
- 返回下标的顺序不限。

### 示例 1

```text
输入：nums = [2,7,11,15], target = 9
输出：[0,1]
解释：nums[0] + nums[1] = 2 + 7 = 9。
```

### 示例 2

```text
输入：nums = [3,2,4], target = 6
输出：[1,2]
```

### 示例 3

```text
输入：nums = [3,3], target = 6
输出：[0,1]
```

## 题解

### 思路：一次遍历与哈希表

最直接的方法是枚举所有下标组合，检查两个元素之和是否等于 `target`。这种方法需要两层循环，时间复杂度为 `O(n²)`。

对于当前元素 `num`，只要找到另一个值为 `target - num` 的元素，就能组成答案。使用哈希表保存已经遍历过的元素，可以将查找另一个数的平均时间缩短到 `O(1)`。

定义哈希表 `seen`，键为元素值，值为该元素在原数组中的下标。从左向右遍历数组：

1. 计算当前元素需要配对的值 `target - num`。
2. 如果这个值已经存在于 `seen` 中，返回当前下标和表中记录的下标。
3. 如果没有找到，将当前元素及其下标写入 `seen`，继续遍历。

以 `nums = [2,7,11,15]`、`target = 9` 为例：

```text
下标 0，当前值 2：查找 7，未找到，记录 seen[2] = 0。
下标 1，当前值 7：查找 2，找到下标 0，返回 [1,0]。
```

题目允许按任意顺序返回下标，因此 `[1,0]` 和示例中的 `[0,1]` 都是有效答案。

### 为什么先查找，再记录

**查找时，哈希表只保存当前下标之前的元素。** 这样命中的下标一定与当前下标不同，可以保证同一个元素只使用一次。

例如 `nums = [3,3]`、`target = 6`：

- 遍历第一个 `3` 时，哈希表为空，查找失败后记录下标 `0`。
- 遍历第二个 `3` 时，查到第一个 `3` 的下标，返回 `[1,0]`。

如果先记录当前元素，再查找配对值，第一个 `3` 就可能匹配到自身，得到两个相同的下标。

Go 查询 map 时需要使用 `k, ok := seen[target-num]` 判断键是否存在。下标 `0` 是合法答案，直接根据查询结果是否为 `0` 判断存在性会产生歧义。

### 正确性说明

遍历到下标 `i` 时，`seen` 中保存的下标都小于 `i`。如果查到 `target - nums[i]`，对应元素与当前元素的和恰好等于 `target`，且两个下标不同，因此返回结果满足要求。

对于唯一答案的两个下标，设它们为 `a < b`。遍历到 `b` 时，`nums[a]` 已经写入哈希表。由于 `nums[a] + nums[b] == target`，查询一定能够命中，算法可以找到答案。即使某个值的下标被后续相同值覆盖，保存的下标仍然早于当前下标，对应数值也保持不变，因此仍然可以组成有效答案。

## 复杂度分析

- 时间复杂度：平均 `O(n)`。数组最多遍历一次，每次哈希表查询和写入的平均时间为 `O(1)`。
- 空间复杂度：`O(n)`。哈希表最多记录 `n` 个不同的元素值。

## Go 代码

```go
func twoSum(nums []int, target int) []int {
	seen := make(map[int]int, len(nums))
	for i, num := range nums {
		if k, ok := seen[target-num]; ok {
			return []int{i, k}
		}
		seen[num] = i
	}
	return []int{}
}
```

题目保证存在唯一答案，合法输入会在遍历中直接返回两个下标。末尾的空切片用于处理遍历结束仍未找到答案的情况。

## 小结

把“两数之和等于目标值”转化为“查找当前元素的配对值”，再用哈希表保存数值与下标的对应关系，就能在平均 `O(n)` 时间内完成搜索。先查找、后记录的顺序保证了两个元素来自不同下标，也能自然处理重复值。
